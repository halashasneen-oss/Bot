## ما يفعله النموذج

1. سوق BTC خمس دقائق فقط، بتوكنين مختلفين وقواعد تسوية موثقة. لا يستنتج القواعد من العنوان. يدعم تسوية terminal أو متوسط آخر 60 ثانية TWAP إذا ثبتت القواعد لذلك السوق؛ لا يختار بين القواعد لتحسين النتائج.
2. توقع واحد عند عمر 180 ثانية، بسماح وصول أقصاه ثانيتان. قائمة النوافذ متتابعة ومعلنة في رأس التسجيل قبل التوقعات. لا يعوض توقعاً فائتاً بتوقع لاحق، ولا يحتسب النافذة مرتين تحت معرفين مختلفين.
3. يتطلب سعر افتتاح مرصوداً عند البداية، ومصدراً موثقاً مطابقاً للقواعد، وتاريخ underlying spot مرصوداً قبل القرار. تاريخ TWAP المتداخل ليس بديلاً عن underlying spot لتقدير التذبذب.
4. خط أساس رياضي بلا انجراف أو مؤشرات مضبوطة على النتائج: `dS = sigma_price dW`. التذبذب هو جذر مجموع مربعات العوائد اللوغاريتمية مقسوماً على مدة التاريخ، ثم يحول إلى وحدات السعر بضربه في السعر الحالي. نافذة 120 ثانية، 60 فترة على الأقل، وفجوة قصوى ثانيتان. لا تُملأ الفجوات.
5. توقع terminal يستخدم تباين `sigma_price² × remaining`. توقع TWAP مستقبلي بطول W يستخدم `sigma_price² × (remaining − 2W/3)`. عند مرور جزء من TWAP يجب توفير المساحة المرصودة الحقيقية حتى الطابع الزمني الحالي؛ لا يستنتجها النموذج. الحساب يبدأ من وقت آخر سعر مرجعي، وليس من وقت وصوله المتأخر.
6. يحسب كلفة 5 أسهم من asks عبر العمق، مع حد انزلاق 0.005 للسهم ورسوم السوق وتكاليف أخرى مثبتة. يشترط edge متوقعاً 0.03 للسهم على الأقل وحد خسارة افتراضية 5 دولارات. شراء NO هو شراء التوكن المقابل، ولا يستخدم بيعاً اصطناعياً دون مخزون.

هذا خط أساس Gaussian غير معاير. لا يعلم أن احتمالاً محسوباً بـ65% صحيح فعلاً، ولا يعتمد على حركة BTC وحدها دون مقارنة بكلفة التوكن. مخاطر القفزات، تغير التذبذب، التقريب الحسابي، وتطابق المرجع قد تجعل التقدير سيئاً. لا يمكن تحويل expected edge إلى ربح محقق.

الرسوم تعتمد على معلمات السوق المرصودة، بمعدل وصيغة exponent=1 مدعومة. الصيغة الرسمية `shares × rate × p × (1−p)`، والرسوم مقربة لخمس منازل. التطبيق يستخدم حداً محافظاً يرفع تقريب رسوم كل مستوى ويأخذ أكبر رسم داخل مجال الانزلاق، وليس رسوماً ثابتة بعشر نقاط أساس. ## المدخل والتشغيل

الوحدة `pairbot.directional` مستقلة عن المحرك القديم. تقرأ JSONL من ملف أو pipe مسمى؛ لا تتصل بالشبكة. الملف القديم من pairbot لا يُقبل. أول سطر:

```json
{"type":"directional_input_header","schema":"btc-directional-v1","synthetic":false,"recording_started_at":1791144600,"first_market_start":1791144600,"market_count":200}
```

تحدد `first_market_start` و`market_count` النوافذ الخمس دقائق المتتابعة مسبقاً. يجب أن يبدأ التسجيل والنوافذ بعد وقت commit التجميد. النافذة بلا قرار تُسجل missing_decision في الوصف وتبقى في المقام. لا يُختلق لها احتمال أو سعر.

كل candidate يحتوي `received_at`، وmarket مع id وasset وslug وstart/end وyes_token/no_token وminimum_shares، وقواعد موثقة لها hash/url/source_id/observed_at، وopening موثق له price/reference_at/received_at. يحتوي reference underlying spot مع تاريخ exchange_at وreceived_at لكل نقطة، وclock، ودفتر snapshots للطرفين، ورسوم مرصودة، وتكلفة أخرى ودليلها. المخطط العملي الكامل موجود في `pairbot/directional_fixture.py`؛ كل ما يولده صناعي وموسوم بذلك.

التسويات تأتي في أسطر resolution لاحقة بـmarket_id وwinner YES/NO وstatus resolved ورابط الدليل وreceived_at بعد نهاية السوق. يجب أن يتحقق المحول من النتيجة الرسمية؛ النموذج لا يستنتجها من سعر BTC أو توكن قريب من دولار. ترتيب الوصول متزايد، وتسوية مبكرة أو مكررة أو توقع بعد التسوية يوقف الجلسة دون تقرير نجاح.

```bash
python -m pairbot.directional --input NEW_PROSPECTIVE.jsonl --journal NEW_PREDICTIONS.jsonl --report NEW_REPORT.json
```

يُنشأ journal جديد حصراً، مع نسخة مدخل القرار وبصمتها وبصمة السياسة وسلسلة hashes؛ يُفلش ويُحفظ fsync قبل معالجة التسوية التالية. سلسلة hashes تكشف العبث العرضي، وليست توقيعاً أو إثباتاً لصحة مصدر خارجي. الملف الناقص لا يقبل كجلسة مكتملة. لا يكتب فوق journal أو تقرير سابق.

تحقق صناعي مستقل، بمسارات جديدة:

```bash
python -m pairbot.directional_fixture --output NEW_SYNTHETIC.jsonl
python -m pairbot.directional --input NEW_SYNTHETIC.jsonl --journal NEW_SYNTHETIC_PREDICTIONS.jsonl --report NEW_SYNTHETIC_REPORT.json
```

فحص جاهزية عام محدود، GET فقط:


## التقييم وقاعدة GO

يعرض التقرير النسخة الكاملة والقرارات النظيفة، عدد النوافذ المعلنة والقرارات والتسويات المتاحة، أسباب الامتناع، ونسبة القرارات المستبعدة. `excluded_time_fraction=null`: هذه عينة نقطة واحدة لكل نافذة، ولا تقيس جودة كل ثانية؛ لا تدعي استبعاد زمن لم يُقَس. تُعرض فجوة التغطية ولا تختفي النوافذ الفائتة.

يقارن Brier للنموذج مع YES mid بوصفه توقع السوق، لا سعر تعبئة. يحسب كذلك payoff bound افتراضياً إلى التسوية عند شراء الكمية المرصودة مع التكاليف؛ ليس PnL، وليس إثبات إمكانية التعبئة. `fills=0` و`realized_pnl=null` دائماً. البيانات الصناعية لا تمنح GO مهما كانت نتائجها.

الشروط المجمدة للقياس PAPER الأطول: بيانات حقيقية جديدة؛ نسبة قرارات نظيفة >=90%؛ >=200 سوق محسوم قابل للتقييم؛ >=50 قرار اختيار محسوم؛ الحد السفلي 95% لتحسن Brier موجب؛ والحد السفلي 95% لحد payoff الافتراضي موجب. bootstrap على مستوى السوق، 2000 تكرار وبذرة ثابتة. نافذة واحدة تُحسب مرة واحدة، ولا تُعد رسائل السوق عينات مستقلة. bootstrap يفترض قابلية تبادل الأسواق، وقد يقلل عدم اليقين عند الارتباط الزمني؛ لهذا يسمح بقياس أطول فقط ولا يثبت الربحية.

أي GO هنا مستقل تماماً عن قواعد القبول السابقة. لا اختبار نهائي قديم ولا تحريك بصمته. لا إعادة ضبط بعد النتائج.
