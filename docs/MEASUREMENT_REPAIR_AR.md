- سجل لكل تفعيل لحارس الحركة/السبريد: السبب، الثواني منذ البداية، السبريد للطرفين، والمدى عند توفره. تقارير replay تربط كل تفعيل بتغير mid بعد 5 و20 ثانية؛ نقص الرصد يظهر `null`.
- توزيعات receive−exchange لكل نوع رسالة ولكل دقيقة، وتوزيع مجموع أفضل bid مرجّحًا بالزمن مع استبعاد فترات قدم الدفتر.
- كل BUY يسجل وجود أمر مقابل وسعره وطابوره وanchor وأول تغير عمق لاحق. SELL فوق limit يسجل الطابور والعمق دون استهلاك الطابور.
- قارئ WebSocket منفصل عن المعالج، `max_queue=256`، وطابور معالجة سعته 4096. امتلاؤه يوقف الاتصال ويطلب إعادة snapshot؛ يسجل الرسائل التي لم تدخل الطابور وتلك التي لم تعالج، ويضيف فجوة.
- journal/التقارير/fsync/sha256/error log تنتقل إلى عامل I/O واحد، بطابور 8192 مع 32 خانة احتياطية لدليل الخطأ/الإغلاق. تقارير CLI تستخدم نسخة بيانات مستقلة، فلا يقرأ العامل حالة المحرك المتغيرة. ضغط طابور I/O يوقف الجلسة مع دليل صريح؛ فشل القرص يفشل الجلسة ولا يعلن نجاح الحفظ.
- flush/checkpoint دوري كل 45 ثانية، وإجباري عند error/status/stop والإغلاق. footer gzip والبصمات والنشر الذري وfsync للدليل وmanifest محفوظة. يتم تفريغ العامل قبل انتهاء collect. ملف `io-timings.jsonl` يحتفظ بوقت كل fsync وsha256 وwrite_report أثناء الجمع؛ p50/p99 للطوابير/المعالجة/تأخر الحلقة تعلن أنها آخر 4096 مشاهدة.
- `guard_mode=up_mid` و`guard_warmup_seconds=0` و`trade_volume_multiplier=1` هي الافتراضيات. الخيارات الجديدة لا تدخل collect الحي؛ تستخدم في replay فقط. معامل الطابور الافتراضي يبقى 1.5.
