# اكتمال تجهيز المسار اليومي — PAPER ONLY

نُفذت الأجزاء البرمجية المتبقية: جامع نتائج رسمية، مقيّم دقة لنهاية الفوج، استعادة أرشيف الأيام، ومشغّل لمحاولة التسجيل. لا يوجد تداول أو تعبئة أو عائد مُختلق. السياسة المجمدة وبصمتها لم تتغير.

## النتائج الرسمية

pairbot.daily_results يقرأ فقط https://data-api.polymarket.com/v2/resolutions باستخدام condition IDs الخاصة بالـuniverse الذي جُمّد داخل journal. كل طلب يحوي حتى 20 condition وفق الوثائق؛ يحفظ جميع الاستجابات والأخطاء. لا lookup قبل وقت الهدف، ولا تعديل لملف التوقعات.

الوسم المقبول يتطلب status=resolved، وقت تسوية واعياً بالمنطقة بعد الهدف وقبل الاستلام، رقم block موجب، وناتج دفع ثنائي فيه رابح واحد فقط، وcondition ID مطابق. ترتيب outcomes من metadata الأصلية يحدد YES/NO. حالة closed أو أسعار السوق 0/1 أو اقتراح التسوية لا تكفي. الوضع غير المدعوم أو الدفع المقسوم يبقى pending، ولا نحاول تخمينه. هذا adapter محافظ؛ شكل API النهائي لم يختبر على فوجنا المستقبلي الذي لم يبدأ.

الأمر:

```sh
python -m pairbot.daily_results --journal runs/daily-prospective/2026-10-06/journal.jsonl --output runs/daily-prospective/2026-10-06/resolution-1.json
```

كل محاولة جمع نتائج ملف جديد مربوط بـSHA256 journal؛ ملف موجود لا يُكتب فوقه.

## مقيّم نهاية الفوج

pairbot.daily_evaluate يرفض حساب الأداء قبل هدف اليوم التسعين (3 يناير 2027)، ويقرأ مجلد daily-prospective وحده، بأسماء الأيام الـ90 المحددة، وليس سجلات أو اختبار المشروع القديم. الأيام الناقصة تبقى null في مواقعها الزمنية؛ لا يُختلق احتمال لتعويضها.

- يعيد اشتقاق الوسوم من الأدلة الرسمية، ويرفض اختلاف journal hash أو تعارض نتائج نهائية.
- للتوقع الحقيقي يعيد حساب الاحتمال وmidpoint من المدخلات المحفوظة وفق السياسة، ويرفض عدم إمكانية إعادة إنتاجهما.
- يعرض نتائج كل عقد وكل يوم، Brier للنموذج والسوق، وفرق Brier، على الفوج الكامل والوصف النظيف، مع نسب النقاط والأيام المستبعدة/الناقصة. الزمن المستبعد null لأن القرار نقطة يومية لا تغطية زمنية.
- معنى اليوم النظيف في التقرير: جميع نقاط universe لذلك اليوم مسجلة وموسومة وقابلة للمقارنة ونظيفة؛ لا تختفي العتبات غير المسجلة من المقام.
- التقدير الاحتمالي يعيد سحب كتل دائرية بطول 7 أيام، 2000 مرة ببذرة السياسة؛ العتبات داخل اليوم ليست عينات مستقلة. الأيام الناقصة لا تزال مواقع في الكتل. كل bootstrap ثابت البذرة، دون مجموعات بديلة.
- CLI ينشئ قفل تقييم نهائي في جذر الفوج، ويرفض ملف ناتج موجوداً. المشغل النهائي محاولة واحدة ولا يجوز إعادة نشر config لنفس اليوم أو إعادة الحساب لتغيير النتائج.

لا بوابة قبول مالي تعمل حالياً: السياسة المجمدة other_costs_usd=null وجميع الأفعال ABSTAIN، وبالتالي selected_resolved_days=0 وnet_payoff=null وقرار NO-GO. لا نضع صفراً مكان الاسترداد ولا نجعل نجاح الدقة ربحاً. البيانات الاصطناعية لا تمنح GO. أرشيف GitHub الخارجي يحتاج تدقيق هوية/وقت/commit مستقلاً؛ hash محلي ليس إثبات وقت، لذلك التقرير الحقيقي يُوسم DESCRIPTIVE_UNAUDITED_ARCHIVE حتى مراجعة ذلك الدليل.

الأمر بعد نهاية الفوج فقط:

```sh
python -m pairbot.daily_evaluate --root runs/daily-prospective --output runs/final-report.json
```

## التشغيل والأرشفة

config/daily-launch.json ينشّط محاولة واحدة بواسطة commit جديد على paper-btc-directional-20261004، وهو trigger تعمل به Actions على هذا الفرع دون merge إلى main. القيمة الحالية enabled=false: اختبار تشغيل غير مسلح فقط. المشغل ينتظر بحد أقصى عشر دقائق إلى وقت القرار +ثانيتين، ثم يتقيد بنافذة ±30 ثانية؛ تأخر Actions لا يُعالج بتوسيع النافذة أو توقع بأثر رجعي.

بعد محاولة اليوم، يستعيد فقط ZIPs المخصصة في docs/daily/captures، يرفض بيانات اصطناعية أو قواعد/فوج آخر، ويجمع النتائج غير النهائية للأيام السابقة. تُحفظ labels منفصلة، وتُعاد مراجعة payouts بدل الثقة بعلم FINAL وحده. يجب أن يحفظ تنفيذ المهمة اللاحقة كل artifact في Git قبل انتهائه، مع metadata خادم GitHub، ويفصل journal الحالي عن نسخ التاريخ لتجنب تكرار اليوم في الأرشيف. لا تُعدّل التوقعات المفقودة ولا تستبدل محاولة سابقة بمحاولة أفضل.

أُنشئت مهمة الجدولة بنجاح في 4 أكتوبر 2026: بدء محاولة قبل القرار بخمس دقائق، 90 يوم تسجيل ابتداءً من 6 أكتوبر 2026، ثم مرور أخير في 4 يناير 2027 لجمع نتائج آخر يوم وإخراج تقرير نهاية الفوج. المهمة مفعلة، وجدولها DTSTART;TZID=America/New_York:20261006T055500 وRRULE:FREQ=DAILY;COUNT=91. نيويورك 05:55 تتغير إلى 13:55 عمّان عند انتهاء DST؛ وقت القرار نفسه يبقى 06:00 نيويورك وفق السياسة. أول إطلاق مجدول هو 6 أكتوبر 12:55 عمّان، والقرار 13:00 عمّان. الدقة في موعد خدمة الجدولة أو طابور Actions غير مضمونة؛ أي فوت يُسجل نقصاً. لن تُعدّل العتبات لإنقاذ يوم فائت.

تفعيل مهمة مستقبلية لا يعني أن تسجيلاً حقيقياً حدث الآن. لا تستطيع البيانات أو الحسابات تعويض اليوم الحقيقي قبل موعده. التقييم النهائي نفسه لا يعني إثباتاً مالياً مع التكاليف المجهولة.
